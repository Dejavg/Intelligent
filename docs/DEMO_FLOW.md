# Demo 演示流程

## 1. 首页

访问：

```text
http://127.0.0.1:8000
```

展示项目名称、项目简介、运行模式、AI 批改结果预览卡、三步演示流程和进入 Demo 按钮。

## 2. 学生上传

1. 点击“进入 Demo”。
2. 选择学生：张三。
3. 选择学科/模式：自动识别。
4. 选择题型：答题卡。
5. 上传固定 5 题数学练习卷图片。
6. 点击“开始 AI 批改”。

系统自动调用：

```text
POST /api/upload
POST /api/ocr
POST /api/grade
```

第一阶段比赛稳定演示建议保持：

```env
DEMO_FIXED_MATH_PAPER_OCR=true
```

此时首页和上传页会显示“当前模式：比赛稳定演示模式”，并用稳定 Demo OCR、逐题批改、过程分、教师复核、班级报告等用户友好标签说明能力；技术配置会以弱化小标签展示。系统会稳定返回结构化 OCR：5 道题的题干、学生答题步骤和整卷标题。真实图片 OCR 可以在第二阶段通过 `DEMO_FIXED_MATH_PAPER_OCR=false` 切回。

真实图片会先进入 OCR 预处理链路。传统 OCR 模式下会执行灰度化、对比度增强、去噪、二值化和倾斜矫正；视觉大模型默认使用原图，可通过 `OCR_PREPROCESS_FOR_LLM=true` 切换为增强图。

## 3. 批改结果

展示内容：

- OCR 识别结果；
- AI 批改分数；
- 对错判断；
- 过程分维度；
- 解题过程分析；
- 错误原因；
- 正确解法；
- 个性化评语；
- 薄弱知识点；
- 学习建议；
- 整张答题卡逐题批改卡片；
- OCR/预处理诊断提示；
- 学生个人薄弱点报告。

比赛讲解重点：

- 总分：`43 / 50`；
- 第 3 题：学生写 `90 - 28 = 72`，系统给 `6 / 10`，标记为“错误”，并指出正确答案为 `62`；
- 第 4 题：移项和合并正确，最后 `3x = 15` 推出 `x = 4` 错误，显示为“部分正确”，得 `7 / 10`；
- 正确题绿色、部分正确黄色、错误步骤红色高亮。
- 右侧总分卡展示 `43 / 50`、正确题、部分正确、需订正、薄弱点和综合评语。
- 逐题卡片展示题干、学生作答、过程分析、错误定位、正确解法、知识点、薄弱点和个性化建议。

## 4. 教师工作台

1. 点击“教师复核”或顶部“教师工作台”。
2. 查看所有学生提交记录。
3. 打开某个学生提交详情。
4. 修改教师分数或评语。
5. 点击“确认复核”。

提交后状态变为：

```text
教师已复核
```

也可点击“返回学生”，状态变为：

```text
已返回学生
```

## 5. 班级分析

进入“班级分析”页面，展示：

- 平均分；
- 正确率；
- 最高分；
- 最低分；
- 薄弱知识点排行；
- 各题正确率；
- 高频错误；
- 教学建议。

点击“导出报告”可下载 Markdown 格式学情分析报告。

## 6. 管理中心扩展演示

进入“管理中心”页面，可展示后续优化已经落成的工程入口：

1. 新增题库题目，验证题库管理能力。
2. 新增班级，验证多班级基础模型。
3. 批量上传 Demo，为多名学生同时创建提交并自动批改。
4. 查看评分准确率评测面板，展示测试样例数、评分误差合格率、错因识别准确率、知识点识别准确率和教师复核一致率。
5. 对某条提交保存教师二次标注，用于后续模型优化闭环。
6. 返回教师工作台或班级分析页，查看新增数据对报告的影响。

## 7. 3 到 5 分钟讲解顺序

1. 首页：说明项目定位为比赛级完整闭环 Demo。
2. 运行模式：说明比赛现场使用 `DEMO_FIXED_MATH_PAPER_OCR=true` 保证稳定，真实 OCR 模式可通过 `DEMO_FIXED_MATH_PAPER_OCR=false` 切换。
3. 上传页：展示步骤条和固定 5 题数学卷说明。
4. 结果页：重点讲第 3 题 `90 - 28 = 72` 被定位为计算错误。
5. 结果页：重点讲第 4 题前两步正确、最后一步错误，因此不是 0 分，而是过程分 `7 / 10`。
6. 教师工作台：展示 AI 原始分数、教师复核分数、差异和二次标注闭环。
7. 班级分析：展示平均分、正确率、薄弱点排行、高频错误和 AI 教学建议。
8. 管理中心：展示评分评测中心，强调系统通过样例验证批改稳定性。
